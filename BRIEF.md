## Problema

O Método PACTO está sendo construído como um framework prático para orientar o desenvolvimento de qualquer solução com agentes de código, como Claude Code, Codex e ferramentas similares.

O projeto já possui pesquisa, templates, regras universais e guia visual, mas precisa aplicar o próprio método em sua estrutura: contratos operacionais na raiz, SPEC da fase atual, plano de continuidade e regras claras para agentes.

## Usuários

- Criador do método: Alexandre Barroso de Miranda, Consultor de Processos.
- Usuários finais: pessoas que querem iniciar projetos com agentes de código sem saber estruturar briefing, stack, documentação, segurança, testes e validação.
- Agentes de código: Claude Code, Codex e equivalentes que precisam de instruções claras para operar no projeto.

## Resultado Esperado

O projeto deve ficar pronto para ser usado como kit e referência prática do Método PACTO, com documentos de raiz que orientem qualquer agente a trabalhar no próprio framework.

## Variáveis Decisivas

### Uso e Escala

- Usuários iniciais: uso pessoal/profissional pelo criador e por pessoas orientadas por ele.
- Usuários simultâneos: não aplicável neste momento, pois é um framework documental.
- Pico de uso: não aplicável.
- Crescimento esperado: pode evoluir para material ensinável, template distribuível, Custom GPT ou kit público.

### Dados

- Tipos de dados: documentação, prompts, templates, relatórios de pesquisa e HTML estático.
- Dados sensíveis: não deve conter segredos, credenciais ou dados reais sensíveis.
- Arquivos e anexos: HTML, Markdown, texto e templates.
- Auditoria/histórico: desejável via Git quando o projeto for versionado.

### IA

- IA é auxiliar ao método, não o produto principal.
- Tipo de uso de IA: briefing assistido, pesquisa, geração de documentos, apoio a desenvolvimento e revisão.
- Pode enviar dados para API externa: apenas materiais sem segredos ou dados sensíveis.
- Limite de custo: não definido.

### Segurança e Acesso

- Login: não aplicável.
- Perfis de acesso: não aplicável.
- Multi-cliente/multi-tenant: não aplicável.
- Requisitos especiais: preservar UTF-8, evitar segredos, checar licenças/termos de assets e dependências.

### Integrações

- APIs externas: nenhuma obrigatória.
- Serviços pagos: nenhum obrigatório.
- Automação: possível no futuro via Custom GPT, skills ou scripts.

### Operação

- Plataforma: documentação e HTML estático.
- Hospedagem desejada: local por enquanto.
- Orçamento de infraestrutura: não aplicável.
- Quem manterá: Alexandre Barroso de Miranda.

### Legal e Licenciamento

- Uso comercial: possível como método/guia profissional.
- Distribuição para terceiros: possível no futuro.
- Restrições de licença: ainda não definidas.
- LGPD/contratos/normas: evitar dados reais sensíveis nos exemplos.
